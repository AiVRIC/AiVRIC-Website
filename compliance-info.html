Framework Support Policy

AiVRIC Framework Support Policy

This policy defines how AiVRIC classifies framework and benchmark versions as Current, how long older versions remain supported, and how AiVRIC communicates changes in checks and mappings between releases. The objective is to keep customers audit-ready while maintaining predictable, transparent updates.

Effective:  2025-12-13 Applies to:  Frameworks, benchmarks, mappings Reviewed:  Quarterly
Summary AiVRIC supports the most recent stable “generally available” versions of major frameworks and benchmarks. When a new version is released, AiVRIC follows a defined intake process, provides a transition window, and publishes a change log describing check and mapping changes.

1) How AiVRIC determines “Current”

AiVRIC designates a framework or benchmark as Current when it meets the criteria below. This reduces ambiguity during audits and helps customers plan upgrades with confidence.

Current designation criteria

  • Official release: the version is published by the issuing organization as an official release (not a draft).
  • Stable reference material: the release includes stable documentation or authoritative reference artifacts.
  • Industry adoption: the version is broadly recognized by auditors and compliance practitioners, or has a formal transition schedule.
  • Implementable mappings: AiVRIC can map checks to controls with definable intent and measurable evidence outputs.
  • Operational viability: the version can be implemented in production without requiring speculative interpretation.

Intake and validation process

When a new framework version is released, AiVRIC uses a structured intake workflow to minimize disruption:

  • Gap review: identify additions, removals, and materially changed controls.
  • Mapping impact analysis: determine where check logic or control mappings must change.
  • Regression validation: validate that existing outputs remain accurate and explainable.
  • Release classification: label changes as Minor (non-breaking), Major (breaking), or Urgent (security-critical).
  • Publication: publish the new support status, timelines, and change log.
Practical interpretation “Current” does not require every customer to upgrade immediately. AiVRIC provides a predictable transition window so customers can align with audit cycles, procurement, and internal change control requirements.

2) Deprecation window for older versions

AiVRIC supports older versions for a defined period to accommodate audit cycles and enterprise change management. Deprecation is handled transparently with a grace period and clear end-of-support dates.

What qualifies as a “breaking” framework update? (expand)

A breaking update is one that materially changes control intent, control identifiers, assessment objectives, or evidence expectations such that prior mappings could be misleading without revision. When AiVRIC detects a breaking change, it is communicated as a Major mapping change with an explicit migration note.

Can a framework be deprecated earlier than 9 months? (expand)

Yes, but only in exceptional cases—such as when an issuing authority sets a hard retirement date, or when a version contains critical inaccuracies that create compliance or security risk. In those cases, AiVRIC will publish an accelerated timeline with at least one release cycle of notice whenever feasible.

3) How AiVRIC communicates changes (checks & mappings)

AiVRIC publishes clear, audit-friendly release communications so customers can understand what changed, why it changed, and what actions (if any) are required. Communication is structured for both engineering and compliance stakeholders.

Release-to-release communications

  • Release notes: high-level summary of new frameworks, integrations, and significant updates.
  • Check change log: added/removed checks, logic updates, severity changes, and evidence output changes.
  • Mapping change log: control mapping additions/removals and rationale for mapping changes.
  • Migration notes: required customer actions when major/breaking changes occur.
  • Support status bulletin: “Current/Grace/Deprecated” updates with dates.

Change classification

AiVRIC classifies changes to help customers prioritize impact:

  • Minor: non-breaking improvements (new checks, clarifications, reporting enhancements).
  • Major: breaking or materially impactful updates (mapping shifts, renamed controls, changed evidence logic).
  • Urgent: correctness or security-critical changes requiring rapid customer awareness.
  • Deprecated: removals scheduled or completed (with dates and alternatives).
